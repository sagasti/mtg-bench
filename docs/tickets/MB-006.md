# MB-006: Errored and timed-out matches censor long games non-randomly

- **Status:** done
- **Severity:** medium
- **Area:** ratings
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

`src/rating/outcomes.ts` keeps finished games of a match that later errored and drops the rest; `matchTimeoutSec: 7200` kills the JVM mid-match. With one fast LLM seat the longest match in `full-llm-1` already took 54 min; two LLM seats or reasoning models will exceed 2 h. Long matches are disproportionately control and game-3 matches, and the slower provider's seat loses its games, all reported only as "N match(es) failed".

## Suggested fix

- Exclude all games of an errored match from ratings by default; report censored games per seat.
- Size `matchTimeoutSec` from measured latency × decisions, or make the cap per game.

## Resolution

2026-10-02 (branch `fix/tournament`). Errored matches are now censored as a documented policy (docs/ANALYTICS.md "Errored matches are censored", HANDOFF.md §6): `outcomesFromMatches` drops every match with `error`, including the games it finished, at both game and match level. `report.md` / `summary.json` list censored matches and the finished games left out, per seat; the raw games stay in `matches.jsonl`. See also MB-017.

Left: sizing `matchTimeoutSec` from measured latency × decisions, or making the cap per game (`forge.ts` timer / `engine.matchTimeoutSec`).

2026-10-02 (branch `fix/methodology`, with MB-014):
- The match cap is sized per game: `engine.matchTimeoutSec` if set, else `gamesPerMatch` × `engine.gameTimeoutSec` (new, default 3600 s: 60 min a game, 3 h for best-of-3; `matchTimeoutSec()` in forge.ts). The committed configs drop their fixed `matchTimeoutSec: 7200` for `gameTimeoutSec: 3600`. A per-game value rather than latency × decisions: decisions per game vary too much to measure in advance, and the per-game budget is one number to raise for slow seats.
- Errored matches are replayed once before being censored: `MatchResult.errorKind` (`infra`, `timeout`, `bridge`, `harness`) says what failed; every kind but `harness` is played again from scratch with the same seats, decks and seed at the end of its round (`<id>-replay`, `replayOf`), in events and in `match`. Only if the replay errors too (or the error was a harness bug) is the pairing censored. report.md lists replayed and censored matches per seat. Checked with the mock engine and fabricated errors in round 1: an infra error whose replay completed (counted from the replay), a timeout whose replay timed out too (censored once), a harness exception (censored, not replayed).
- Docs: docs/ANALYTICS.md "Errored matches are replayed once, then censored", docs/AGENTS.md, HANDOFF §6.
