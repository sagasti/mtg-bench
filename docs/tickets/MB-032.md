# MB-032: Forfeits on mandatory selections press OK with fewer than min picks

- **Status:** open
- **Severity:** high
- **Area:** bridge / game integrity
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

On a forfeit (`InputDriver.java:447-449`, also `503-505`) the driver clicks `cancel` if enabled, else `ok`, without checking `okEnabled`. Forge's `selectButtonOK()` doesn't check the button state, and `InputSelectManyBase.onOk()` doesn't check `min`. The harness's forfeit choice ("first legal options") is discarded. Example: an agent that fails 4 times on an edict sacrifices nothing; a forced discard discards nothing. Both seats' results are corrupted, invisibly.

## Suggested fix

- When cancel is disabled, apply the harness's forfeit choice through the normal selection path; never click OK unless `okEnabled`.
