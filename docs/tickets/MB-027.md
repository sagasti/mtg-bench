# MB-027: Swiss pairing can dead-end and crash the event; crashed runs report as complete

- **Status:** done
- **Severity:** medium
- **Area:** tournament
- **Source:** tournament pipeline review (Fable), 2026-10-02; reproduced on the mock engine, key claims re-verified in code

## Problem

`schedule.ts:44` throws "no Swiss pairing without rematches" when the greedy by-points history leaves no perfect matching; `rounds` is unbounded (`config.ts`). Reproduced (mock, seed 7): `rounds: 7` died at round 6 after 20 matches, with no `run_end`, no report, engine not closed. `bench report` on the crashed dir showed no sign it was incomplete.

## Suggested fix

- Validate `rounds <= n-1`; when pairing fails, allow the minimum number of rematches.
- `summarize` flags runs without `run_end` (and pods without `pod_end`) as INCOMPLETE in report.md and summary.json.

## Resolution

2026-10-02 (branch `fix/tournament`). `validateConfig` requires Swiss `rounds` between 1 and seats − 1 (7). `swissRound` no longer throws on a dead end: it searches with an increasing rematch allowance, so it returns the pairing with the fewest rematches, and `run.ts` logs the round's rematch count. `summarize` flags runs without `run_end` and pods without `pod_end` as **INCOMPLETE** at the top of report.md and in summary.json (`incomplete`). Checked: `rounds: 8` is rejected at config load; `rounds: 7` on the mock smoke config completes all 28 matches; 2,000 simulated seven-round Swiss events with random results all complete, with 464 rounds needing one rematch each (the old pairing threw in every one of them); a copy of a run with `pod_end`/`run_end` stripped reports INCOMPLETE.

Note: a crash elsewhere in the event loop still exits without closing the engine or logs (there is no try/finally around the pod loop); such a run is now visibly INCOMPLETE.
