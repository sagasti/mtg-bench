# MB-057: The exclusion rule counts recovered provider retries as failures

- **Status:** done
- **Severity:** medium
- **Area:** analytics / methodology
- **Filed:** 2026-10-03

## Problem

Source: `runs/llm8-lsv-1` final report. gpt-oss-120b is listed "Excluded from the leaderboard" at a 5.3% failure rate with 0 forfeits and 0 fallbacks: all 56 counted "API errors" are HTTP 429 rate-limit attempts that succeeded on retry. Package A records every failed provider attempt as an API error (a usage row with `error`); package D's exclusion rule (MB-012) sums forfeits + fallbacks + API errors per decision. Together they exclude a seat for its host's rate limiting, which never affected its play. gemini-flash-lite (11.6%: 60 forfeits, 70 API errors) is also partly affected, and its forfeits are partly harness-inflated (MB-055, MB-056).

## Suggested fix

- Count, per decision, whether the provider ultimately failed (an infra error) rather than counting retry attempts; keep attempt-level API errors in the reliability table as information.
- Base the exclusion rule on decisions the seat didn't make as configured: forfeits, fallbacks, and decisions that ended in a provider failure.
- Re-run `bench report runs/llm8-lsv-1` after the fix; note in the report which forfeits came from interface issues fixed since (MB-052/055/056).

## Resolution

Done 2026-10-03 (`fix/harness`). The exclusion rule (`src/analytics/report.ts`) now sums, per seat, forfeits (harness
and bridge) + fallbacks + **provider-failure decisions**: decision rows with `infraError`, i.e. decisions whose provider
call still failed after all of the provider layer's retries (the match was then abandoned and replayed). The
denominator is the seat's decisions including those. Attempt-level API errors (every failed provider attempt, most
recovered by a retry) no longer count; they stay in the reliability table ("API errors (attempts)") and in the excluded
table ("API errors (info)") as information. docs/ANALYTICS.md describes the rule.

`bench report runs/llm8-lsv-1` re-run with the fix (only report.md rewritten):

- before: excluded gemini-flash-lite (11.6%: 60 forfeits, 0 fallbacks, 70 API errors, 1125 decisions) and gpt-oss-120b
  (5.3%: 0 forfeits, 0 fallbacks, 56 API errors, 1065 decisions);
- after: gpt-oss-120b is ranked (2nd, 1587, 1415–1953); gemini-flash-lite is still excluded at 5.7% (60 forfeits,
  0 fallbacks, 4 provider failures, 1129 decisions; 70 API errors shown for information).

Not done: the report doesn't separate forfeits caused by interface issues. MB-055 and MB-056 (the likely sources of
part of gemini-flash-lite's and mistral-small's forfeits) are still open on the bridge side, so there was nothing
"fixed since" to attribute; re-check gemini-flash-lite's exclusion once they land.
