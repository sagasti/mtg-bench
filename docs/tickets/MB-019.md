# MB-019: Tokens of decisions that end in infra errors are missing from the cost tables

- **Status:** done
- **Severity:** medium
- **Area:** analytics
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`agent.ts:115` throws `InfraError` before `recorder.decision(...)`; `report.ts:30-42` sums tokens and cost from decision rows only. Tokens spent before the failure are in `usage.jsonl` but not in the cost columns. No error has occurred yet in a recorded run, so current totals match.

## Suggested fix

- Record the decision row (with `error`, `infraError`) before throwing, or compute cost from `usage.jsonl`.

## Resolution

2026-10-02 (branch `fix/tournament`). `summarize` now takes tokens, model calls, computed cost and reported cost from `usage.jsonl` call rows (by seat, seat × phase and decision kind); decision counts, validity, latency and tool use still come from `decisions.jsonl`. Calls whose decision has no row (it ended in an infrastructure error) are counted and the cost section names how many per seat. On a mock run with no errors the regenerated report.md is byte-identical to the old one; with two of echo-a's decision rows removed, its tokens and cost are unchanged (597 decisions, 734 calls) and the report notes the 2 calls.

With `fix/llm-layer` writing a decision row with `infraError: true` before throwing, such rows are counted as infra-error decisions in the reliability table and excluded from decision counts and provenance; their tokens are already in the call-based totals, so nothing is counted twice.
