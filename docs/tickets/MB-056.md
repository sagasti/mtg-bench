# MB-056: X prompts offer 0–30 regardless of mana, and failed X casts give no feedback

- **Status:** done
- **Severity:** high
- **Area:** bridge / interface
- **Filed:** 2026-10-03

## Problem

Source: `runs/llm8-lsv-1` (gameplay-analysis review of gpt-6-luna, verified 2026-10-03). Since MB-045 every `choose_number` X prompt lists 0 to min+30 ("Choose X for Forth Eorlingas!", 31 options), with no indication of available mana. When the chosen X can't be paid, the cast is cancelled silently and the agent is asked at priority again with no explanation; e.g. `p0-r1-deepseek-flash-vs-gpt-6-luna-replay` g1: X=30, then X=16, both failed. gpt-6-luna made at least 35 failed X casts across the event (Forth Eorlingas!, Mind Twist), wasting whole turns; 89 `choose_number` decisions were made in the run overall. The failure is charged to the agent's play, but the interface hid both the limit and the reason.

## Suggested fix

- Bound X options by what can actually be paid: use Forge's own max for the announcement where it provides one, else compute from available mana (the same estimate as the affordability filter, accounting for coloured pips), and say in the prompt "you have N mana available; X costs …".
- When a cast is cancelled because its cost can't be paid, tell the agent in the next prompt ("Forge cancelled Forth Eorlingas!: X=30 needs 32 mana; you had 8"), as already done for other rejections.
- Re-check the reliability numbers of seats with X spells in this run when reporting it.

## Resolution

- **X bounded by what can be paid.** `AgentControllerHuman.announceRequirements` handles X in a mana cost itself: it
  offers Forge's minimum up to the largest X the seat can pay (`Playability.maxPayableX`: Forge's AI payer, or, where
  it refuses, the rules-only estimate of MB-058 with colours matched shard by shard), at most 30 above the minimum, and
  words the question "Choose X for Forth Eorlingas! (mana cost {X}{R}{W}). Your untapped sources and floating mana make
  about 8 mana, so X can be at most 6." When only the minimum can be paid it's taken without asking (forced, "X: only
  the smallest value can be paid"). X in other costs (life, tapped creatures: Toxic Deluge, Myr Battlesphere) keeps
  Forge's own bound (`getMaxForNonManaX`) and question.
- **Failed casts are explained.** When the bridge cancels a cast because its cost can't be paid, the agent's next
  question carries "(Since your last decision: Forge cancelled casting Forth Eorlingas! with X=9: {9}{R}{W} was still
  owed and couldn't be paid (your untapped sources and floating mana make about 8 mana))"; a declined "unless you
  pay" says so too.

Validation (same runs as MB-055, 29 games each): X questions listed 30.7 values on average (31 almost always) before,
8.0 after (2-21); all 88 mana-X questions state the available mana and the maximum (the other 10 were Toxic Deluge's
life X and Myr Battlesphere's tapped-Myr X, Forge's own); 7 X values were forced (only the minimum payable). "Cost
can't be paid: cast cancelled" 144 -> 18, and each of the 18 reached the agent as a "Forge cancelled ..." notice in
its next prompt. In `runs/llm8-lsv-1`, 75 X questions averaged 30.0 values.

Code-review follow-up (2026-10-03): the override now applies Forge's bound for an X that also appears in a non-mana
cost part (`Cost.getMaxForNonManaX`, as Forge's own `announceRequirements` does), before the mana bound. Check: echo
with 14 Bond of Agony ({X}{B}, pay X life) and fast mana against a Castle Vantress deck, 3 matches each. Without the
bound, 66 of 218 Bond X questions offered X above the seat's life; with it, 0 of 135.
