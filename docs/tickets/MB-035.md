# MB-035: The forfeit null action on yes/no questions is 'Yes'

- **Status:** open
- **Severity:** medium
- **Area:** bridge / provenance
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

`forfeitChoice` (`src/agents/agent.ts:160-166`) looks for `meta.type === "pass"`, then id `no`, else the first options. Dialog confirms use ids `o1…` with Yes first, and the driver tags OK as `pass` on every non-casting input, including optional `InputConfirm`s. So a failing agent answers Yes to "You may sacrifice a creature?", contrary to the documented null action (decline).

## Suggested fix

- Give the decline option a stable id (`no`) or `meta.type: "decline"`; tag OK as `pass` only on priority and mulligan inputs.
