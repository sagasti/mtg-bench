# MB-028: --pools-from restores post-deckbuild notes before re-running deckbuild

- **Status:** done
- **Severity:** low
- **Area:** re-run
- **Source:** tournament pipeline review (Fable), 2026-10-02; reproduced on the mock engine, key claims re-verified in code

## Problem

Notes are saved after the draft and overwritten after deckbuild (`run.ts:88,92`, same file), and pools mode restores that file before `buildDeck`, so the "fresh" deckbuild sees the seat's earlier final list.

## Suggested fix

- Save post-draft notes separately (e.g. `notes/<seat>.draft.md`) and restore those in pools mode.

## Resolution

2026-10-02 (branch `fix/tournament`). Post-draft notes go to `pod<N>/notes/<seat>.draft.md`, post-deckbuild notes to `<seat>.md`. `--pools-from` restores the `.draft.md` file; `--decks-from` restores `<seat>.md`. A source from before the split has no post-draft notes, so pools mode starts deckbuild without notes and logs that, rather than using the post-deckbuild ones.
