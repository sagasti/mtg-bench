# MB-029: Loaded decks are never validated

- **Status:** done
- **Severity:** low
- **Area:** re-run / match
- **Source:** tournament pipeline review (Fable), 2026-10-02; reproduced on the mock engine, key claims re-verified in code

## Problem

`resume.ts:48-52` and `match.ts:19-23` use deck JSON/.dck files as-is: no size, basics, card-DB or pool check; Forge silently drops unknown names when loading a `.dck`.

## Suggested fix

- Validate against `minDeckSize`, the basics whitelist, the card DB and (for `--decks-from`) the seat's drafted pool.

## Resolution

2026-10-02 (branch `fix/tournament`). `deckProblems` (src/deckbuild/deckbuild.ts) checks a loaded deck against `minDeckSize`, the card DB, the basics whitelist (`basics` keys must be basic lands) and, when given, the seat's drafted pool. `--decks-from` checks every saved deck (with the pool from the source's `draft.jsonl` when it has one, and the deck's `seatId`) before the run dir is created; `bench match` checks both deck files the same way, without a pool. Verified on the mock engine with a 32-card deck containing an unknown card and an undrafted one.
