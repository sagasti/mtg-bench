# MB-015: Harness exceptions become agent forfeits, and forfeit rows drop the error

- **Status:** open
- **Severity:** medium
- **Area:** harness
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`agent.ts:112-114` turns any throw in `LlmAgent.decide` (rendering, template read, `assertNoLeak`) into `response: null` → forfeit charged to the agent; the decision row stores `error` only for fallbacks (`agent.ts:135`). Example: an event name of 4+ characters that appears in the seat's own study brief (e.g. "pauper") trips `assertNoLeak` on every later decision: a silent stream of forfeits.

## Suggested fix

- Treat non-provider exceptions as harness errors (abort like `InfraError`).
- Always persist `error` on forfeit rows.
