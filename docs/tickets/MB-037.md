# MB-037: Block retries can only add blockers, never remove them

- **Status:** done
- **Severity:** medium
- **Area:** bridge
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

After a rejected block declaration, assigned blockers stay in combat and aren't offered again (`CombatUtil.canBlock` is false for a creature already blocking), so the agent can only add blocks; past the budget the seat forfeits even when the fix was to remove one.

## Suggested fix

- Clear the seat's blocks before re-asking for the full set, as the prompt already claims.

## Resolution

Before each block ask the seat's block assignments are undone (`Combat.undoBlockingAssignment`), so the agent always answers with the full set; blocks are validated before OK (MB-036). In the bot runs rank-3 met menace (Goblin Freerunner): the reason ("cannot be blocked with 1 creatures you've assigned") went back on each re-ask and, as rank-bot repeated the same block, it forfeited to no blocks. Commit 94fa793.
