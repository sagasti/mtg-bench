# MB-024: Re-using a --run-id appends to the existing run and corrupts it

- **Status:** open
- **Severity:** high
- **Area:** tournament / logging
- **Source:** tournament pipeline review (Fable), 2026-10-02; reproduced on the mock engine, key claims re-verified in code

## Problem

`Jsonl` opens files with `"a"` (`src/util/log.ts:9`) and `run.ts:39` reuses an existing run dir, so a retried or repeated run appends to `draft.jsonl`, `matches.jsonl`, `events.jsonl`, `decisions.jsonl` and `usage.jsonl` while overwriting `config.json`, decks and the report. Reproduced: running `--run-id dup-a` twice gave 56 matches in one report; `--pools-from dup-a` then built decks from 90-card pools without complaint.

## Suggested fix

- Refuse to start when the run dir exists (or require `--force` and wipe it).
- `SourceRun` rejects sources with more than one `run_start` or duplicate `pod_start`.
