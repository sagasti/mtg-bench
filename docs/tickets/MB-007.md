# MB-007: maxGameTurns isn't enforced on the default (human) bridge

- **Status:** open
- **Severity:** medium
- **Area:** bridge
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

The 40-turn draw cap is only checked in `PlayerControllerExternal.java:278` (legacy `ai` path); `MatchContext.maxTurns` is never read by `InputDriver`/`AgentGuiGame`. `full-llm-1` has games of 43, 59 and 64 turns, none ending in a draw. Two passive LLM seats could play a very long game at full token cost.

Bridge review confirms: only `PlayerControllerExternal.java:278` reads `ctx.maxTurns`; suggested: check the turn in `AgentGuiGame.isUiSetToSkipPhase` or `InputDriver.step` and end the game with `GameEndReason.Draw`, recorded.

## Suggested fix

- Enforce the cap on the human path (AgentBridge game loop or AgentGuiGame) and record the end reason.
- Decide and document how draws enter the ratings.
