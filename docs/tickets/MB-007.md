# MB-007: maxGameTurns isn't enforced on the default (human) bridge

- **Status:** done
- **Severity:** medium
- **Area:** bridge
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

The 40-turn draw cap is only checked in `PlayerControllerExternal.java:278` (legacy `ai` path); `MatchContext.maxTurns` is never read by `InputDriver`/`AgentGuiGame`. `full-llm-1` has games of 43, 59 and 64 turns, none ending in a draw. Two passive LLM seats could play a very long game at full token cost.

Bridge review confirms: only `PlayerControllerExternal.java:278` reads `ctx.maxTurns`; suggested: check the turn in `AgentGuiGame.isUiSetToSkipPhase` or `InputDriver.step` and end the game with `GameEndReason.Draw`, recorded.

## Suggested fix

- Enforce the cap on the human path (AgentBridge game loop or AgentGuiGame) and record the end reason.
- Decide and document how draws enter the ratings.

## Resolution

Enforced on every path: `AgentBridge.TurnCap` subscribes to `GameEventPlayerPriority` and, once the turn passes `maxGameTurns`, gives both players a draw outcome and ends the game (`GameEndReason.Draw`); end reason "Draw (turn cap of N turns)", no winner. Forge counts every player without an outcome as a winner, so the AI-controller path's cap had recorded draws as wins; fixed there too. Tested with `maxGameTurns: 8` (`runs/cap8b`: every game a draw at turn 9). Commit 94fa793. Left: decide and document how draws enter the ratings (rating code).

2026-10-02 (branch `fix/methodology`). Decided: a turn-cap draw scores 0.5 for each seat at game level (a match with equal game wins scores 0.5 at match level), which Bradley-Terry already supported; draws are kept, not dropped, since letting games stall is part of a seat's play. Documented in docs/ANALYTICS.md "Draws" and HANDOFF §6. report.md's Games section and summary.json (`cappedDraws`) give turn-cap draws per seat (`cappedDrawsBySeat`, matching the bridge's "Draw (turn cap of N turns)" and the mock's `turn-cap`).
