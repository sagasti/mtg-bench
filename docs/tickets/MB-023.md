# MB-023: SeatConfig.concurrency is documented but never read

- **Status:** done
- **Severity:** low
- **Area:** config
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`config.ts:262` defines it; nothing uses it. The draft fires all 8 seats at once and parallel matches add more in-flight calls per provider, so rate limits surface as API errors and abandoned matches (MB-014).

## Suggested fix

- Implement a per-provider/seat semaphore, or remove the option.

## Resolution

On `fix/llm-layer` (770334b): `concurrency` is implemented as a per-seat limit on in-flight model calls
(`limitConcurrency`, `src/agents/providers/types.ts`), validated as a positive integer; queue time is not charged to the
decision clock. Unset means no limit, as before. A per-provider (shared key) limit is not implemented.
