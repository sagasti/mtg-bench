# MB-031: Attack retries never reach the budget and re-asks invert the agent's choice

- **Status:** open
- **Severity:** high
- **Area:** bridge
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

`InputAttack.onOk()` doesn't validate; `PhaseHandler.declareAttackersTurnBasedAction` validates and opens a new `InputAttack` with the same `combat`. Each rejection is a fresh input, so `drive()` resets `declarations` and the forfeit/`AiAttackController` path (`InputDriver.java:346-365`) is unreachable for attacks. On the re-ask, already-declared attackers are offered with "Remove from combat", so picking the same creature again undeclares it. A model that keeps answering "none" under an attack requirement loops until `matchTimeoutSec`.

## Suggested fix

- Count attack retries per combat/turn, not per input.
- Before re-asking, remove the seat's attackers so the question is a clean "choose the set"; forfeit/delegate past the budget.
