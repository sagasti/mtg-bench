# MB-052: An agent can mulligan forever from an empty hand

- **Status:** open
- **Severity:** medium
- **Area:** bridge / provenance
- **Filed:** 2026-10-02

## Problem

Source: `runs/llm8-lsv-1`, `p0-r1-qwen-flash-vs-mistral-small` game 2. After losing game 1, mistral-small's own match notes said "Mulligan aggressively for a fast start"; in game 2 it mulliganed down to 0 cards and kept answering Mulligan about 950 more times (18:11–18:28 UTC, ~1 call/s, 991 calls, $0.11) with `hand: []` in its prompt, before eventually keeping. Forge keeps offering keep/mulligan at any hand size and the rules set no cap, so nothing stopped it.

## Suggested fix

- Mulligan floor: when another mulligan can't produce a smaller hand (London mulligan at 0 cards to keep), the keep is forced and recorded as forced ("no smaller hand possible").
- A general repeated-identical-decision guard (same input, same answer, unchanged state, N times) alongside the loop rule (MB-046), so the next variant is caught too; recorded and counted in the report.
- The decision stays scored: mulliganing to zero is the model's choice; only the endless repetition is cut off.
