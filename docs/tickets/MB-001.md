# MB-001: Pods, not games, are the replication unit; one pod can't separate models

- **Status:** in progress
- **Severity:** high
- **Area:** methodology
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

A seat keeps one drafted deck for every game of a pod, so its games are correlated through the deck. Identical bots differ by 300+ Elo within one pod (`full-llm-1`: forge-ai-2 1889 vs forge-ai-1 1561; `human-bots-9`: 2027 vs 1691). The bootstrap in `src/rating/bt.ts` resamples matches, not pods, so the quoted 95% CIs (±200–280 Elo) are still too narrow for model-vs-model claims. All configs use `pods: 1`.

## Suggested fix

- Run the all-bot line-up over 5–10 seeds (free) and publish each bot's between-pod rating SD: the benchmark's noise floor.
- Report per-pod ratings and bootstrap over pods (or fit BT with a per-(seat, pod) random effect).
- Size real events from the noise floor (rough estimate: ~20 pods to resolve ~100 Elo).

## Resolution

2026-10-02 (branch `fix/methodology`). Each outcome carries its pod (run + pod index). With more than one pod, `rate` (src/rating/bt.ts) bootstraps in two stages: pods with replacement, then matches within each drawn pod; with one pod it resamples matches as before, and report.md says the CI then leaves out pod-to-pod variation. `podRatings` fits each pod alone; report.md has "Ratings by pod" (one column per pod, merged runs labelled by run) with each seat's SD between pods, and summary.json `podRatings`. Policy in docs/ANALYTICS.md "Pods are the replication unit". Checked on a 3-pod mock run (`--pods 3`): pod bootstrap and the per-pod table with SDs of 91–226 Elo.

Left: the noise-floor experiment (the owner is running the all-bot line-up, `runs/noise-floor-lsv-1`), publishing each bot's between-pod SD from it, and sizing real events from that.
