# MB-004: Seats aren't in the same reasoning regime or on pinned hosts

- **Status:** in progress
- **Severity:** high
- **Area:** methodology / config
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

`config/forge-8llm.yaml` disables reasoning, but gemini-2.5-flash-lite ignored it (256k reasoning tokens of 265k output in its sanity game); gpt-oss-120b, gpt-5-nano and glm-5.3-flash refuse to disable it (now `effort: low`). Only DeepSeek's host is pinned: in one game glm-flash was served by 5 hosts and gpt-oss-120b by 3, with different quantizations and prices.

## Suggested fix

- Make each seat's reasoning setting and host part of the event spec, and verify them from `usage.jsonl` (e.g. `check --ping` asserts zero reasoning tokens when disabled and the pinned `servedBy`).
- Pin `provider.order` + `allow_fallbacks: false` per seat.
- Treat reasoning on/off as two seats of the same model when it matters (ablation).

## Resolution

On `fix/llm-layer` (786923b, f91bcd9):
- Every call is checked against the seat spec (`checkSeatSpec`, `src/agents/llm.ts`): reasoning tokens when the seat
  disables reasoning, or a `servedBy` host outside a pinned `provider.order` with `allow_fallbacks: false`. A breach is
  logged as a WARNING once per seat and marked `specViolation` on the usage row and the decision row; `check --ping`
  prints reasoning tokens and host per seat and lists a breach as a problem.
- `config/forge-8llm.yaml` pins every seat (`provider.order` + `allow_fallbacks: false`) to the host that served most of
  its calls in `runs/sanity-*` (DeepSeek: Baidu, from `full-llm-1`), and sends Gemini 2.5 Flash Lite
  `reasoning: { max_tokens: 0 }` (OpenRouter maps it to Gemini's `thinkingBudget`; 0 turns thinking off on 2.5 Flash /
  Flash-Lite) instead of the ignored `enabled: false`.
