# MB-030: 'End Turn' / 'Undo' buttons at priority silently yield the rest of the turn

- **Status:** open
- **Severity:** high
- **Area:** bridge / provenance
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

`InputPassPriority` enables Cancel labelled "End Turn" (or "Undo (n)"), and the driver offers it as a normal option. Forge's `onCancel()` → `autoPassUntilEndOfTurn()`, after which `chooseSpellAbilityToPlay` returns null for every remaining priority this turn and `declareAttackers` returns early, with no input and nothing recorded. Verified in run data: 1,852 recorded decisions chose "End Turn", including every LLM seat (DeepSeek 5 in `full-llm-1`; 7–17 per model in each sanity game). The opponent-reveal `InputConfirm("OK","End Turn")` does the same. Similar helpers: `InputLondonMulligan`'s cancel is "Auto" (Forge picks the bottom cards), unrecorded.

## Suggested fix

- Never offer the cancel button on `InputPassPriority`, the reveal confirm, or London-mulligan "Auto"; or keep `shouldAutoYield()` false for agent seats.
- If "end turn" is ever wanted as a feature, implement it as a recorded policy.
