# MB-003: Provider errors and truncated outputs are scored as the agent's mistakes

- **Status:** open
- **Severity:** high
- **Area:** harness / validity
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

`runs/sanity-gemini-flash-lite/usage.jsonl`: 58 of 257 calls returned HTTP 200 with `finish_reason: "error"` and no output. `providers/openai.ts` doesn't treat this as an error, so `llm.ts` nudges and retries as if the model had answered badly, and decisions end as forfeits; the report shows "API errors 0". Separately `maxTokens: 2048` is shared by reasoning and answer: qwen-flash stopped on `length` in 28/108 calls (DeepSeek 53/1730), each burning a retry. `decisionTimeoutSec` timeouts become infra errors that abandon the match (see MB-006).

Harness review adds: `llm.ts:114-125` handles a `length` stop like prose (salvage/nudge); `full-llm-1` 53/1730 calls and `human-llm-1` 14/484 were truncated; for reasoning models the cap can be consumed entirely by reasoning, ending in a forfeit.

## Suggested fix

- Classify `finish_reason: error` / empty responses as provider errors: retry with backoff, don't count as invalid answers or forfeits, and count them in "API errors".
- Give the answer its own budget (raise `maxTokens`, or set it per family by a documented rule); report the `length`-stop rate per seat.
- Detect `length`/`max_tokens` stops and retry with a larger cap; record truncation per decision.
- Fix before the paid 8-LLM event.

## Resolution

2026-10-02, report side only (branch `fix/tournament`; the provider/harness changes are on `fix/llm-layer`): the reliability table shows each seat's truncated calls (usage rows with `truncated`) as a share of its calls, and decisions abandoned by an infrastructure error (`infraError` rows) are counted in their own column and never as agent decisions or forfeits. A timed-out decision (`timedOut`) counts as a forfeit and is labelled "timed out" in the forfeit table.
