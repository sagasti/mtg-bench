# MB-061: Mana payment forces one source per mana owed, though some sources make several

- **Status:** done
- **Severity:** medium
- **Area:** bridge / interface
- **Filed:** 2026-10-03

## Problem

Source: `runs/llm8-lsv-1`, gameplay review of glm-flash (r5 G2 T8 "extra picks are redundant but required", r5 G3
T12 "prompt requires at least 4 sources"). The `mana_payment` question asked with min = the mana still owed and said
"N mana in total, so pick at least N source(s)", as if every source made one mana. Sol Ring, Mana Crypt, Ancient Tomb
(2), Black Lotus, Mana Vault (3) make more, so the agent had to list sources it didn't need (and, by the same count,
"exactly enough sources" pressed Auto when the sources merely numbered no more than the mana owed, though a 3-mana
source could pay alone). 143 `mana_payment` prompts in the run had such a source among the options; in 89 of them the
minimum asked for exceeded the fewest sources that could pay.

## Resolution

`InputDriver` reads each source's output for this payment from Forge (`Playability.manaFrom`: the most any of its
mana abilities makes, `totalAmountOfManaGenerated`) and:

- asks with min = the fewest sources whose outputs, largest first, cover what is owed (max = all sources); the prompt
  says "N mana still owed, so choose sources that together make at least N mana (at least K source(s)). Sources are
  tapped in the order you list them, and tapping stops once the cost is paid." and a source making more than one mana
  is labelled "(makes 3 mana)";
- treats a payment as "exactly enough sources" (forced) only when every source is needed by that count;
- offers only sources that can make a type of mana still owed (`Playability.helpsPay`): Forge's payment input marks
  every source with a playable mana ability, so a Forest was listed for {B}, and picking it changed nothing until the
  retries ran out (a forfeit).

Extra picks aren't tapped: the chosen sources are clicked one per step, and the payment input closes as soon as the
cost is paid, which discards the rest of the queue (`drive` stops when the input is no longer current and clears the
queue for the next input).

Validation (the MB-055 runs, 29 games each, master bridge vs this branch): `mana_payment` questions with a source
making more than one mana among the options asked for more sources than needed in 132 of 221 before, 0 of 286
after. In an after-run game log, a {1} activation answered with three sources tapped only the first, and a {2}
cycling answered with four tapped two. "Chosen sources never completed the payment" forfeits: 1 before, 0 after (5 in
a first round without the "can make a type still owed" filter, from echo picking a Forest for {B}).
