# MB-060: "unknown option id" forfeits: agents answer with the whole option line, not the id

- **Status:** open
- **Severity:** medium
- **Area:** harness / validation
- **Filed:** 2026-10-03

## Problem

Source: `runs/llm8-lsv-1`, gameplay review of gpt-5-nano (14 forfeits on multi-select mana payments, crew and
priority, all "unknown option id"). The suspicion was that option ids change while a question is open.

Investigation (2026-10-03): they don't. A multi-select question is asked once per step with a fixed option list
(`InputDriver`: mana sources `c<cardId>`, crew/choose-cards `c<cardId>`), and the harness re-asks within the same
request (`LlmAgent.decide`), so the ids an agent sees and the ids it is checked against are the same list. What the
rows show is the answer format: the 41 "unknown option id" rows in the run quote what the model sent as the id, and 18
of gpt-5-nano's 19 are whole option lines: `"[c82] Pay mana with card: your Plains"`, `"[c131] select card: your Cat
Token 2/2"`, `"[ok] Button: OK"`, `"[ok]"` (the 19th is `"cast:k01"`). mistral-small's 14 are `"cast:c28"`-style
ids, one label, and ids of cards in its hand that weren't offered (e.g. `c63`, Force of Negation, filtered at the
time); gemini-flash-lite's 8 are ids not in the list (including 2 draft picks) and `"pass"`. The rejection message ("Rejected: unknown option id
"[c82] Pay mana with card: your Plains". Choose again from the Options list.") doesn't tell the model what an id looks
like, and gpt-5-nano repeated the same format through all 4 re-asks each time.

So it isn't a bridge bug, and the bridge can't fix it: the answer is validated in the harness (`src/types.ts`
`validateResponse`, message used by `src/agents/llm.ts`).

## Suggested fix (harness, owner's call)

- Make the rejection say what an id is: `unknown option id "[c82] Pay mana with card: your Plains": use only the id in
  square brackets, e.g. "c82"` when the answer contains a bracketed option id, and list a few valid ids otherwise.
  This keeps the answer the model's own (no silent repair) and costs nothing.
- Don't accept "[c82] ..." as "c82" silently: that would change what is measured (formatting the answer is part of the
  task), and would need a decision-log entry.
- Re-check gpt-5-nano's exclusion-rule numbers after the change.
