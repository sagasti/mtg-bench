# MB-017: Errored matches still award standings points and match-level results

- **Status:** open
- **Severity:** medium
- **Area:** ratings / tournament
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`forge.ts:81-83` computes `winner` from completed games even on timeout/crash/infra error; `run.ts:124` awards points from it regardless of `res.error`; `outcomes.ts` match level uses `m.winner`, and game level only skips games whose reason starts with "error", which the dropped in-progress game never has. A bridge crash at 1–0 counts as a match win (present in `human-bots-5`/`-6`). Related: MB-006.

Tournament review adds: a match that errored with no games is a draw at match level and gives 1 Swiss point each (reproduced).

## Suggested fix

- Give errored matches `winner: null` for standings and match-level ratings; report them separately.
- Document whether completed games of an errored match count at game level (MB-006 recommends not).
