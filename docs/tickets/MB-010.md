# MB-010: No version provenance in run artifacts; bridge depends on Forge internals

- **Status:** open
- **Severity:** medium
- **Area:** architecture
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

`config.json`/`events.jsonl` record neither the harness commit, bridge jar hash, Forge commit, card-DB build nor rankings file. The human bridge reads Forge fields by reflection (`InputSelectManyBase.min/max`, `validChoices`, `manaCost`), scans thread stacks for `InputPayMana` tasks, and keys progress off prompt/button text, so a Forge upgrade can break it silently.

## Suggested fix

- Record harness commit (+dirty flag), bridge jar SHA, Forge commit, `cards.json` hash and rankings hash in `run_start`.
- Add a bridge conformance check (fixed-deck bot matches with known outcomes/decision counts) to run after any Forge bump.
