# MB-010: No version provenance in run artifacts; bridge depends on Forge internals

- **Status:** done
- **Severity:** medium
- **Area:** architecture
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

`config.json`/`events.jsonl` record neither the harness commit, bridge jar hash, Forge commit, card-DB build nor rankings file. The human bridge reads Forge fields by reflection (`InputSelectManyBase.min/max`, `validChoices`, `manaCost`), scans thread stacks for `InputPayMana` tasks, and keys progress off prompt/button text, so a Forge upgrade can break it silently.

## Suggested fix

- Record harness commit (+dirty flag), bridge jar SHA, Forge commit, `cards.json` hash and rankings hash in `run_start`.
- Add a bridge conformance check (fixed-deck bot matches with known outcomes/decision counts) to run after any Forge bump.

## Resolution

2026-10-02 (branch `fix/tournament`). `collectProvenance` (src/util/provenance.ts) records the harness commit and whether tracked files had uncommitted changes, the engine, the Forge commit (when `forgeDir` is itself a git checkout) and jar name, the bridge jar's SHA-256, and the SHA-256 of `data/cards.json` and of the rankings file actually loaded (`rankingsFile` in src/cards/cube.ts). `run` and `match` write it to `config.json` and `run_start`; report.md has a "Versions" section (one line per run; older runs say "not recorded") and summary.json a `versions` list. Checked against `~/forge-src`: Forge commit 2ccbbb01326e, jar `forge-gui-desktop-2.0.15-SNAPSHOT-jar-with-dependencies.jar`, bridge jar hash, both data hashes.

Left: the bridge conformance check (fixed-deck bot matches with known outcomes/decision counts) to run after a Forge bump.

2026-10-02 (branch `fix/methodology`). `bench conformance <config> [--update] [--baseline FILE]` (src/tournament/conformance.ts): four bot-only best-of-3 matches (rank-bot vs random, random vs rank-bot, rank-bot vs rank-bot, rank-bot vs forge-ai) with fixed decks (`conformance/decks/`, four rank-bot/forge-ai decks from `runs/merged-bots-1`), fixed seeds and fixed event settings, fresh random streams per match, two at a time. Engine settings come from the config. Each match is summarised (match error kind, games, game-end kinds, engine exceptions, `[bridge error]` lines in the Forge log, decisions per seat and kind, forfeits, delegations) and compared with `conformance/baseline.forge.json`: exact on match errors, engine exceptions, bridge errors and game-end kinds not in the baseline; tolerant on counts (games ±1, decisions per seat and kind ±max(10, 50%), per-seat totals ±max(20, 25%), forfeits and delegations ±max(3, 50%)), since the same seed replays the same games only up to the bots' and Forge AI's random state. Baseline committed from Forge 2ccbbb01326e with this branch's bridge jar; six runs on that commit gave identical summaries, the check passed twice against the committed baseline, and a perturbed baseline was flagged (a decision kind off by 200, an engine exception, a new end reason; a +3 drift passed). "Run after any Forge bump" is in docs/FORGE_SETUP.md, HANDOFF T4 and §6.
