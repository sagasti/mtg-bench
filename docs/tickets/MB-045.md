# MB-045: An unbounded number prompt floods the harness until it runs out of heap

- **Status:** done
- **Severity:** high
- **Area:** bridge / human path; harness
- **Source:** all-bot LSV noise-floor run (`runs/noise-floor-lsv-1`), 2026-10-02: the Node process died with
  "JavaScript heap out of memory" (4 GB) about 6 minutes in, during pod 0, with every output file under 2 MB

## Problem

Not a per-match leak. Reproduced with the same config at 3 pods under `--max-old-space-size=512`, logging
`process.memoryUsage()` every 5 s: heapUsed stayed at 59-61 MB through pod 1 and into pod 2, then climbed from 60 MB
to 512 MB within 40 s and the process died. The heap snapshot taken at the limit held 3,212,488 objects
`{seat, game, what: "free_text", reason: "free-text input (e.g. naming a card) not offered in the spike"}` in the
`delegations` array of one `ForgeEngine.playMatch` closure (245 MB of strings, 178 MB of objects; nothing else above
40 MB). In the original run the match still open at the crash was `p0-r7-random-1-vs-rank-3`; its log ends with the
bridge's game thread inside `AbstractGuiGame.getInteger` → `AgentGuiGame.showInputDialog` → `AgentChannel.delegated`
when the harness connection dropped.

Forge's number prompt for an unbounded value (an X announcement, `PlayerControllerHuman.announceRequirements`) lists
min..min+9 plus "Other...". "Other..." opens a free-number input (`showInputDialog`, numeric, no options), which the
bridge answered with Forge's initial input `""`, recording a delegation. Forge re-asks until it gets a number, so the
bridge sent a delegation message as fast as it could forever, and the harness kept every one. A random seat picks
"Other..." one time in eleven.

## Resolution

- `AgentGuiGame.getInteger(message, min, max, cutoff)` offers one bounded list, min..min(max, min+30) (the
  AI-controller bridge's `announce_x` cap), as a `choose_number` decision; none chosen cancels, as in Forge.
- `AgentGuiGame.showInputDialog` answers a free-number input with null (cancel) instead of `""`, so nothing can
  re-ask it forever.
- `ForgeEngine.playMatch` ends a match as a bridge error once it has received over 100,000 delegations or forfeits,
  so a future bridge loop costs one match rather than the event.

Verified: 12 random-1 vs rank-3 matches on the pod-0 decks without errors (9 bounded 31-value number questions
answered). heapUsed after a full GC at the start of each pod, same 3-pod config (seed 1000) under
`--max-old-space-size=512`:

| Run | Pod 1 | Pod 2 | Pod 3 | End |
|---|---|---|---|---|
| before | 50.8 MB | 59.1 MB | (died in pod 2: 60 → 512 MB in 40 s) | OOM |
| after | 50.5 MB | 58.9 MB | 59.4 MB | 58.1 MB |

The 5 s samples stayed between 59 and 86 MB through all three pods after the fix (the 167 MB peak is the final
ratings bootstrap and report), including 20 minutes of the Chain of Smog loop (MB-046), ~50,000 decisions, at 61 MB.
