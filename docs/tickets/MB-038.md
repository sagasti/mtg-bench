# MB-038: An exception in step() re-drives the same input forever

- **Status:** done
- **Severity:** low
- **Area:** bridge / robustness
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

`InputDriver.run()` catches the Throwable and loops; the 1 s fallback re-drives the still-open input and `drive()` resets its budgets, so a repeatable exception logs an error every second until the 2 h match timeout.

## Suggested fix

- Count consecutive failures per input and abort with the thread dump after a few.

## Resolution

`InputDriver.run` counts consecutive failures on the same input; after 3 it reports a bridge error, dumps the threads and exits (the match ends as an error). Verified by code reading. Commit 94fa793.
