# MB-036: Every Forge notification is shown to the agent as a rejection of its last choice

- **Status:** done
- **Severity:** medium
- **Area:** bridge / prompts
- **Source:** Java bridge review (Fable), 2026-10-02; traced in the bridge and Forge 2ccbbb01; key claims re-verified

## Problem

`AgentGuiGame.message()` sets `lastError`, but `notifyOfValue` routes all notifications there (chosen colour, coin flips, reveals). The next prompt says "Forge rejected your last choice: P2 wins the flip". `InputBlock.onOk` posts its real validation error asynchronously, so the retry may not see it and a later prompt does.

## Suggested fix

- Separate notifications (informational) from rejections (`showErrorDialog`, `flashIncorrectAction`); validate blocks synchronously (`CombatUtil.validateBlocks`) to get the reason.

## Resolution

`AgentGuiGame.message` is a rejection only when its title is "Cost payment invalid" or "Error"; every other message (notifyOfValue, "no cards in zone") is a notice shown with the next decision as "Since your last decision: ...". Blocks and attacks are validated synchronously with `CombatUtil.validateBlocks` / `validateAttackers` before OK, and the reason is passed to the agent on the re-ask, so `InputBlock`'s asynchronous message no longer arrives late.
