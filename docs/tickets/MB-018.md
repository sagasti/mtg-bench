# MB-018: Provenance inflated: match notes counted as in-game agent decisions; re-asks counted separately

- **Status:** in progress
- **Severity:** medium
- **Area:** analytics
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`agent.ts:77-87` records `match_notes` with phase `game`, so they count as agent decisions (and failures as in-game forfeits) in `report.ts:104-108`; DeepSeek's 1,468 "agent" decisions in `full-llm-1` include 9 notes rows. Each bridge re-ask of the same step is a separate agent decision (MB-013's `-42`/`-43`).

## Suggested fix

- Give match notes their own phase; count re-asks of one in-game step as one decision with attempts.

## Resolution

Agent side on `fix/llm-layer` (786923b): match notes are recorded with phase `between_games` (usage and decision rows),
so the report's in-game provenance (`d.phase === "game"`) no longer counts them. `DecisionRequest.attempt` is new: when
an engine sets it on a re-ask of the same step, the decision row records `attempt`.

Left (files outside this change):
- Bridge: `AgentChannel.ask` should send an `attempt` (0 first, 1.. on re-asks of the same input/step) with each
  decision message; `InputDriver` knows when it re-asks (`batches`, `repeats`, the AI bridge's `attempt` loops).
- `src/engine/forge/forge.ts`: copy `msg.attempt` into the `DecisionRequest`.
- `src/analytics/report.ts`: count rows with `attempt > 0` as attempts of the previous decision, not new decisions.
2026-10-02, report side (branch `fix/tournament`): the in-game provenance table counts only decisions with phase `game` and also skips `match_notes` rows, so older runs that logged notes as `game` are corrected too. Checked by adding four `match_notes` rows with phase `game` and one with another phase to a copy of a mock run: echo-b's agent count is unchanged (716).

Left (other side): give match notes their own phase in `agent.ts` and record `attempt` on decision rows (and have the bridge send it), which the report changes below rely on.

Also report side: rows with `attempt > 0` (a bridge re-ask of the same in-game step) are counted as re-asks in the reliability table, not as new decisions, and don't add to the provenance agent count; `infraError` rows are skipped in provenance. `forge.ts` copies the bridge's `attempt` into the `DecisionRequest` (optional `attempt` field in src/types.ts).
