# MB-048: Rendering Ertai Resurrected's rules text crashes the input driver

- **Status:** done
- **Severity:** medium
- **Area:** bridge / state view
- **Source:** 3-pod all-bot LSV validation run for MB-043..045 (seed 1000, pod 3, `p2-r6-rank-2-vs-random-1`),
  2026-10-02

## Problem

The bridge exited with code 3 after "3 consecutive failures on InputPassPriority". Each failure was a
NullPointerException while building the state for a question: `StateView.card` → `Card.getAbilityText` →
`Trigger.replaceAbilityText` → `CharmEffect.makeFormatedDescription` → `makePossibleOptions` →
`TargetRestrictions.getAllCandidates`, which reads `sa.getActivatingPlayer().getGame()` on a modal ("choose up to one
—") triggered ability that has no activating player. The card was random-1's Ertai Resurrected (the only modal trigger in
either deck), which rank-2 had just targeted in random-1's graveyard (possible since MB-043) with a reanimation spell;
rank-2's deck has Animate Dead.
Every later question re-built the same state, so the match couldn't continue. The harness renders each visible card's
live rules text (Forge's GUI shows a tracked copy instead), so it reaches a Forge path the GUI doesn't.

## Resolution

`StateView` calls Forge's live renderers through `rendered(...)`: if one throws, a fallback stands in and the bridge
sends a warning, once per game and message, instead of failing the decision. Rules text falls back to the card's
printed Oracle text; Forge's card-detail text and a stack object's text fall back to nothing (audit of StateView's
other live Forge calls: those two are the remaining text renderers; the rest read plain fields). The harness counts
warnings per match (`matches.jsonl` `warnings[]`, `[bridge warning]` lines in the Forge log), report.md lists them
under "Bridge warnings", and `bench conformance` prints them.

Regression: a new conformance fixture, `animate-vs-ertai` (rank-bot with `conformance/decks/deck-animate.json`, six
Animate Dead and removal, vs rank-bot with `deck-ertai.json`, ten Ertai Resurrected). On the old bridge 1 of 4 matches
of that pairing crashed the same way (and its replay); on the fixed bridge 8 of 8 finished with no bridge errors and
"rules text of Ertai Resurrected couldn't be rendered (NullPointerException); printed Oracle text shown" counted in
the games where it happened. The conformance check is exact on bridge errors and match errors, so a regression fails
it.
