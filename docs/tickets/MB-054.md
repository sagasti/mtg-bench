# MB-054: A pinned host's outage costs whole matches

- **Status:** done
- **Severity:** medium
- **Area:** harness / providers
- **Filed:** 2026-10-02

## Problem

Source: `runs/llm8-lsv-1`, `p0-r1-deepseek-flash-vs-gpt-6-luna` at 1–1: Baidu (DeepSeek's pinned host, `allow_fallbacks: false`) returned 502 "JSON error injected into SSE stream" / provider_unavailable from 17:50 to at least 17:59 UTC; 7 attempts failed and the match was abandoned as infra (replayed at the end of the round; Baidu answered a ping by 18:23). Rate limits (429) also hit mistral-small 39× and gpt-oss-120b 11×, all recovered. Pinning keeps host and quantisation constant, but a single host's outage longer than the retry window loses matches.

## Suggested fix

- Longer patience for transient provider errors (502/503/429/provider_unavailable): retry with capped backoff for up to e.g. 15–30 minutes; backoff is already excluded from the agent's clock (MB-014), so it costs only wall time.
- Optional backup hosts per seat with the same model and quantisation, used only after the primary fails; `servedBy` already records the host per call, and the report should flag seats served by more than one host.

## Resolution

Done 2026-10-03 (`fix/harness`).

- **Patience.** `postJson` (`src/agents/providers/types.ts`) retries transient failures with backoff from 2 s,
  doubling, capped at 60 s (Retry-After honoured, capped too) until `event.providerRetryWindowSec` (default 1200 s)
  has passed since the call's first failure. Transient: HTTP 429, 408, 529, 5xx, network errors, in-body error objects
  whose code is one of those or whose text says provider_unavailable / unavailable / overloaded / rate limit / timeout /
  "JSON error injected into SSE stream", Anthropic overloaded / rate-limit / api errors, and `finish_reason: "error"`
  unless the native reason is a content block. Failures that may be deterministic (empty answers, other in-body errors)
  keep 7 attempts. Backoff stays off the agent's clock (MB-014). The window is optional with no default entry, so
  `config/forge-8llm.yaml` keeps its config hash (33494a73fed4…, unchanged); `check --ping` uses a 60 s window.
- **Backup hosts.** `backupProviders: [slug, ...]` on an OpenRouter seat: within a call, after two consecutive
  failures on a host the next one is tried, pinned alone (`order: [slug]`, `allow_fallbacks: false`); a host failed
  over from is skipped by new calls for 5 minutes, then the primary comes first again. Once every host has failed, the
  backoff keeps growing as for one host. Backups pass `checkSeatSpec`; `servedBy` records who answered; the report opens
  with **SERVED BY MORE THAN ONE HOST** for such seats (counting answered calls only). Validation: openrouter only, a
  non-empty list, no repeats, not the primary. Documented in docs/AGENTS.md and as comments in
  `config/forge-8llm.yaml` (no seat changed: picking same-quantisation backups is the owner's call).

Offline checks (fake fetch, short windows): in-body 502 "JSON error injected" ×3 then an answer: recovered in 4
attempts; a 429 storm of 1.5 s inside a 3 s window with a 1 s decision clock: recovered, clock not expired; 503 for
ever with a 2 s window: infrastructure error after 12 attempts, "still failing after 2s; retry window 2s"; Baidu down,
DeepInfra up: answered by DeepInfra on the 3rd attempt, the next call went straight to DeepInfra, spec check passed;
both hosts down: gave up at the window after 9 attempts; HTTP 400: no retry.
