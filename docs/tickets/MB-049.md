# MB-049: Deckbuilding is one blind shot: show the agent its deck's stats and allow revisions

- **Status:** done
- **Severity:** medium
- **Area:** prompts / interface
- **Filed:** 2026-10-02

## Problem

Source: `runs/llm8-lsv-1` (2026-10-02). The v2 deckbuild prompt already says "build exactly 40 unless you have a reason not to" and "15-17 lands counting basics", yet decks came out at 51, 45, 40, 40, 41, 40, 44 and 48 cards; qwen-flash built 51 cards with 29 lands (20 basics + 9 nonbasic, ~57%) and played off-colour cards (Palace Jailer WW, Lutri UR, Through the Breach R) on Island/Swamp basics; gpt-6-luna built a five-colour deck on 11 lands with 3 basics. The agent answers once with option ids and a basics count and never sees the resulting deck, so card counting and colour tallying (bookkeeping, not Magic judgement) are error-prone. A human deckbuilding client shows the count, curve and colour breakdown.

## Suggested fix

- Two-step deckbuild (prompt version v3): the agent proposes; the harness returns derived stats (total cards, lands and mana sources, curve, coloured pips required vs coloured sources available, cards whose colours have no source); the agent confirms or revises (1–2 revision rounds). Derived information only, so it's free information under the Regular-REL rule; every judgement stays with the agent.
- Record the help level as part of the setup and keep it identical for all seats; run "no summary" vs "with summary" as a paired ablation (deckbuild costs ~$0.01 per seat per pod), feeding the cross-build stage score (docs/EVALUATION-PLAN.md).
- Don't add more prose rules to the prompt instead: that measures instruction-following.

## Resolution

Done 2026-10-03 (`fix/harness`) as prompt version **v3**: `prompts/v3` is `prompts/v2` with one paragraph added to
`deckbuild.md` and a new `deck-review.md`. When the prompt version has `deck-review.md` (v2 doesn't, so v2 runs are
unchanged), `LlmAgent.decide` treats a valid deck as a proposal and answers it with derived figures
(`src/deckbuild/stats.ts`): total cards (pool + basics) vs the minimum, lands (basic / other), non-land mana sources
and their colours, the curve of non-land cards by mana value, coloured symbols per colour (and in how many cards) vs
the cards that can make that colour (basic land types, Forge `AB$ Mana` abilities, fetch lands by the deck's lands they
can find; hybrids listed apart), and cards needing a colour nothing in the deck makes. The agent submits the same deck
to confirm or a different one to revise; proposals 1 and 2 are reviewed and a third, different deck is final, so at
most two revisions. Each review step gets a fresh `decisionTimeoutSec`. If the agent fails after a valid proposal
(invalid answers, the clock, the provider), its latest proposal stands rather than a rank-bot fallback, recorded in
`deckReview.error`. Decision rows record `deckReview: { proposals: [{ cards, lands }], confirmed }`.

`config/forge-8llm.yaml` stays on v2 (its config hash is unchanged); select v3 with `event.promptVersion: v3`
(docs/PROMPTS.md "Prompt versions"). The help level is the prompt version, recorded in the config hash and the run's
`prompts/` copy, identical for every seat; the v2 vs v3 paired ablation is the owner's call (paid).

Checks: mock event with prompts v3 (`mb049-mock-v3`): both echo seats proposed 47 cards, got the review, revised to 40
and confirmed (`deckReview {"proposals":[{"cards":47,"lands":20},{"cards":40,"lands":20}],"confirmed":true}`), and
played 40-card decks; the same event on v2 (`mb049-mock-v2`) made one deckbuild call per echo seat as before. On
qwen-flash's real pool from runs/llm8-lsv-1 its 51-card deck reviews as 51 cards, 27 lands (20 basic), W: 3 symbols
in 2 cards vs 4 sources, R: 1 symbol vs 4 sources, U/R and W/B hybrids 2 each.

Not done: a report table of deck-review outcomes per seat (the rows carry the data). If the harness keeping the last
proposal after a failure should count as a mechanism acting for the seat, docs/DECISION-PROVENANCE.md needs a line
(another branch is editing that file).
