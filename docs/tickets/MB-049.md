# MB-049: Deckbuilding is one blind shot: show the agent its deck's stats and allow revisions

- **Status:** open
- **Severity:** medium
- **Area:** prompts / interface
- **Filed:** 2026-10-02

## Problem

Source: `runs/llm8-lsv-1` (2026-10-02). The v2 deckbuild prompt already says "build exactly 40 unless you have a reason not to" and "15-17 lands counting basics", yet decks came out at 51, 45, 40, 40, 41, 40, 44 and 48 cards; qwen-flash built 51 cards with 29 lands (20 basics + 9 nonbasic, ~57%) and played off-colour cards (Palace Jailer WW, Lutri UR, Through the Breach R) on Island/Swamp basics; gpt-6-luna built a five-colour deck on 11 lands with 3 basics. The agent answers once with option ids and a basics count and never sees the resulting deck, so card counting and colour tallying (bookkeeping, not Magic judgement) are error-prone. A human deckbuilding client shows the count, curve and colour breakdown.

## Suggested fix

- Two-step deckbuild (prompt version v3): the agent proposes; the harness returns derived stats (total cards, lands and mana sources, curve, coloured pips required vs coloured sources available, cards whose colours have no source); the agent confirms or revises (1–2 revision rounds). Derived information only, so it's free information under the Regular-REL rule; every judgement stays with the agent.
- Record the help level as part of the setup and keep it identical for all seats; run "no summary" vs "with summary" as a paired ablation (deckbuild costs ~$0.01 per seat per pod), feeding the cross-build stage score (docs/EVALUATION-PLAN.md).
- Don't add more prose rules to the prompt instead: that measures instruction-following.
