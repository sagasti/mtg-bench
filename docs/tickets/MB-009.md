# MB-009: Cube contamination; bot-only computed hints; coarse decision kinds on the human path

- **Status:** done
- **Severity:** medium
- **Area:** information policy
- **Source:** architecture & methodology review (Fable), 2026-10-02; key claims re-verified against run artifacts

## Problem

Hiding the cube name buys little: DeepSeek's Pauper-cube brief identifies the cube's archetypes from the list, and `search_cube` returns it. Bots get computed hints (`incomingLethal`, `blockerSurvives`) that LLM seats don't, by design but unstated next to ratings. `AgentGuiGame.getChoices` reports discard, London-mulligan bottom, scry and play/draw as `choose_cards`, so the by-kind tables mislabel them.

Tournament review adds: the coin-toss play/draw choice is recorded as `choose_cards` on the human path (5 in `human-bots-9`, 0 `play_draw`).

## Suggested fix

- Add a held-out or novel cube condition.
- State the bot-hint asymmetry in the report.
- Map Forge inputs to the finer `DecisionKind`s in `src/types.ts`.

## Resolution

Decision kinds on the human path now follow `src/types.ts`: `AgentControllerHuman` (a `PlayerControllerHuman` subclass) names the question while Forge asks it: play_draw, london_bottom (the London mulligan input), discard, scry / surveil (and scry_order / surveil_order), cost_choice (delve), pay_or_else, optional_costs; two-button confirms map to confirm (Yes/No), choose_color (two colours) or choose_option. Commit 94fa793. Left: held-out cube condition; stating the bot-hint asymmetry in the report.

2026-10-02 (branch `fix/methodology`). report.md states the asymmetry under the ratings whenever a bot seat played: an "Information asymmetry" note listing the tags rank-bot reads (from src/agents/bots.ts: option `type`, `cmc`, `sorcerySpeedOk`, `keep`, `toughness`, `evasive`, `attackerPower`, `blockerSurvives`, `killsAttacker`, `hostile`; question hints `handLands`, `handSize`, `opponentMaxUntappedPower`, `incomingLethal`), that random reads none and that forge-ai is Forge's own AI. The held-out cube condition is the owner's call (which cube): written up in HANDOFF §7 and split out as MB-042.
