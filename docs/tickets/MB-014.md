# MB-014: A decision timeout abandons the whole match as an infrastructure error

- **Status:** open
- **Severity:** high
- **Area:** harness / ratings
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`decisionTimeoutSec` (180 s) covers all model calls of a decision, including tool rounds, re-asks and HTTP retry sleeps in `providers/types.ts:146-170` (which ignore the abort signal and can wait up to 60 s per 429). When it fires, `llm.ts:103` returns `infraError`, `forge.ts:114-117` abandons the match, and the game in progress is discarded. Slow but correct models (reasoning, heavy tool use) lose games non-randomly. Related: MB-006.

## Suggested fix

- Separate the agent's time budget (exceeding it = forfeit of that decision, like a chess clock) from provider failure (infra).
- Exclude backoff time from the decision clock; make retry sleeps honour the signal.
- Replay or resume abandoned games instead of dropping them.
