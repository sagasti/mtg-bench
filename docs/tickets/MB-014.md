# MB-014: A decision timeout abandons the whole match as an infrastructure error

- **Status:** done
- **Severity:** high
- **Area:** harness / ratings
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

`decisionTimeoutSec` (180 s) covers all model calls of a decision, including tool rounds, re-asks and HTTP retry sleeps in `providers/types.ts:146-170` (which ignore the abort signal and can wait up to 60 s per 429). When it fires, `llm.ts:103` returns `infraError`, `forge.ts:114-117` abandons the match, and the game in progress is discarded. Slow but correct models (reasoning, heavy tool use) lose games non-randomly. Related: MB-006.

## Suggested fix

- Separate the agent's time budget (exceeding it = forfeit of that decision, like a chess clock) from provider failure (infra).
- Exclude backoff time from the decision clock; make retry sleeps honour the signal.
- Replay or resume abandoned games instead of dropping them.

## Resolution

On `fix/llm-layer` (786923b):
- `DecisionClock` (`src/agents/providers/types.ts`) replaces `AbortSignal.timeout`. `postJson` pauses it while backing
  off and refunds the duration of failed attempts, so `decisionTimeoutSec` counts the model's time only. Retry sleeps
  honour the abort signal; `Retry-After` is capped at 60 s; the second retry loop in `llm.ts` is gone.
- Running out of the budget is the agent's failure: the decision is forfeited (deckbuilding: rank-bot fallback) with
  `timedOut: true` and the reason in `error`; the match goes on. Provider failures after retries stay infrastructure
  errors.

Left: replaying or resuming abandoned games (third bullet; with MB-006 and `src/tournament/resume.ts`).

2026-10-02 (branch `fix/methodology`). Abandoned matches are replayed, not resumed: a match that errored for any reason but a harness bug (provider failure after retries, match timeout, bridge crash) is played once more from scratch with the same seats, decks and seed at the end of its round, recorded as `<id>-replay` with `replayOf`; it stands in for the match in standings and ratings, and only a replay that errors too is censored. Resuming mid-match would need Forge to restore a game state, which it can't. Details and the check in MB-006.
