# MB-013: Mandatory targets arrive with min 0; empty answers accepted; rank-bot answers [] (root cause of MB-002's forfeits)

- **Status:** done
- **Severity:** high
- **Area:** bridge / bots / validation
- **Source:** harness code review (Fable), 2026-10-02; top findings re-verified in code and run artifacts

## Problem

The human bridge sends target selections with `min` from `gui.selMin` (`InputDriver.java:~421`), which is 0 even for "Select a player". `validateResponse` (`src/types.ts:116`) accepts `[]`, the decision is recorded as a valid agent choice, the bridge clicks OK with nothing selected, and after 4 re-asks the cast is cancelled as a forfeit. rank-bot (`src/agents/bots.ts:116-121`) returns `[]` whenever no option is hostile and min is 0 (`hostile.length >= 0` picks the empty hostile list): rank-3 gave 220 empty target answers in `full-llm-1`. LLMs hit it too: `human-llm-1` `h2h-3-…-g1-42`, where the prompt didn't say the model was mid-cast of its own Rend Flesh and it answered `[]`.

Bridge review adds the mechanism: `InputSelectTargets` calls `setSelectables(choices, min, max)` in its constructor, before `InputDriver.update()` resets `selMin/selMax` to 0/MAX, and `ownBounds()` doesn't cover `InputSelectTargets`. So every targeting prompt reads "Choose 0 to N" (42 in `human-llm-1` alone). Fix: snapshot bounds per input or read `numTargets`/`getMinTargets()` by reflection.

## Suggested fix

- Bridge: send the ability's real min/max (`TargetRestrictions.getMinTargets/getMaxTargets`) and name the spell/ability being cast in the prompt.
- rank-bot: fall back to `req.options` when no option is hostile.
- Harness: reject `[]` for `targets` when targets are mandatory.

## Resolution

Bridge: targeting bounds come from the input's own ability by reflection (`numTargets`, else `sa.getMinTargets()/getMaxTargets()`, less the targets already chosen), so "Select target creature" reads "Choose 1 at once"; the prompt starts "You are casting X; choose its targets." (or "Your opponent is ..."). Commit 94fa793. rank-bot falls back to all options when none is hostile, so it never answers `[]` while a target exists. Commit 70df6b6. Harness: with real bounds `min` is 1 for mandatory targets, so `validateResponse` already rejects `[]`; no change needed in `src/types.ts`. rank-3 targeting forfeits: 55 (full-llm-1) / 30 (human-bots-9) before, 0 after (see MB-002).
