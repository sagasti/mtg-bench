# MB-047: rank-bot accepts pointless optional copies

- **Status:** done
- **Severity:** medium
- **Area:** bots
- **Source:** the Chain of Smog loop of MB-046, 2026-10-02

## Problem

rank-bot had no rule for yes/no questions: the `default` branch of `RankBot.choose` picks the first option, "Yes".
Asked whether to copy Chain of Smog back at an opponent with an empty hand, it always copied, which does nothing for
it and lets Forge's AI (which copies whenever its own hand is empty) copy it straight back.

## Resolution

rank-bot (now `v3`, `BOT_VERSIONS` in src/agents/bots.ts) answers "no" to an optional copy of a discard spell while
the opponent's hand is empty, and "yes" to other optional effects as before. The bridge tags a yes/no question about
an optional effect with `api` (the effect) and, for a copy of a spell, `copies` (the copied spell's effect), set in
`AgentControllerHuman.confirmAction` and passed by `InputDriver`; they're bot-only hints (listed in report.md's
"Information asymmetry" note) and never reach LLM prompts.

Decision: "no" wasn't made rank-bot's default for every optional effect. Most "may" effects in the cube help their
controller (draw, search, return a card), so a blanket "no" would make the anchor much weaker for one rare loop, which
the loop rule (MB-046) ends anyway for every seat. Anchor version bumped, so its ratings aren't pooled with v2 runs.

Verified: 8 forge-ai-2 vs rank-2 matches on the pod-2 decks: rank-bot declined 3 copies, accepted 7, every game ended
normally (see MB-046).
